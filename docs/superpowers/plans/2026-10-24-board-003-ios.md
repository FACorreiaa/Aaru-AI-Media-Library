# BOARD-003 Board on iPhone, iPad and Mac Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The friends-only Board in the SwiftUI app, with the same surfaces as BOARD-002 on the web. Friends opens on Board (an inline composer, then friends' posts sorted Recent or Top this week), and Lately becomes its second view. A post screen holds the thread, and a title shows "From friends".

**Architecture:**
- The thread and display rules are pure Swift in `AaruCore`, unit-tested in `AaruCoreTests`. The iOS app has no test target, and `Streak` already sets the precedent for "rule in AaruCore so every client agrees".
- An `@Observable BoardModel` in `aaru-ios/Aaru/Board/` calls the already-generated `/v1/board*` operations, in the same shape as `SocialModel`.
- The views live in `aaru-ios/Aaru/Board/` and are built from Aaru tokens and existing pieces: `Monogram`, `PosterView`, `RatingStars`, `SpoilerMenu`, `SpoilerVeil`, `TitlePickerSheet`, `LibraryStatus.label(for:)`.
- There are no API changes.

**Tech Stack:** Swift 6, SwiftUI with Observation, the iOS and macOS multiplatform target `aaru-ios/Aaru` (`PBXFileSystemSynchronizedRootGroup`, so new files need no pbxproj edit), the generated `AaruAPI` client, and swift-testing in `aaru-core`.

**Spec:** `docs/superpowers/specs/2026-10-22-boards-and-ask-aaru-design.md` (Part 1, iOS), as amended by the BACKLOG decision of 2026-10-23 ("Board on Friends, post page, inline composer"). The web build it mirrors is in `aaru-client/src/lib/board/model.ts`, `aaru-client/src/components/board/*`, and the routes `_shell.app_.friends.index.tsx` and `_shell.app_.friends.posts.$postId.tsx`.

## Owner decisions (2026-10-23, carried to iOS)

- The Board lives **inside Friends**. `FriendsContent` opens on **Board**, and a `Board | Lately` segmented control switches to **Lately**, which is today's `FriendsView` content, unchanged.
  - On iPhone, Friends is reached from Groups' "Friends" toolbar button, as it is today.
  - On iPad and Mac it is the `.friends` sidebar item.
  - There is no tab rename, no router change, and Groups is untouched.
- Comments open on a **post screen**, pushed in the Friends navigation stack.
- The composer is an **inline box at the top** of Board that grows on focus. There is no floating button and no sheet for writing. The title picker is a sheet, as everywhere else.

## Review Focus

1. **Empty Board.** With no friends, or friends who haven't posted, Board shows the owl empty state and still offers the composer.
   - No friends: "Posts from your friends show here. Invite someone from Lately."
   - Friends, no posts: "Nothing yet. Say what you're watching."
   - `boardEmpty` is tested in Task 1 and wired in Task 3.
2. **A comment page that comes back empty but carries `next`.** "Show more comments" stays while `next` is set, and "No comments yet" never shows while `next` is set. `shouldLoadMore` is tested in Task 1 and used in Task 4.
3. **An optimistic upvote that fails.** The count and the filled state roll back, and the problem banner says why. `toggleUpvote` is tested in Task 1 and the rollback lands in Task 2.
4. **Deleting a comment that has replies.** The comment stays as a muted "Comment deleted" row with no author, and its replies stay under it. Deleting the last live reply under a deleted parent removes both. `dropComment` is tested in Task 1.
5. **A review of a title you already have.** The composer line reads "Updates your rating to ★★★★½. Its status stays."
   - For a new title, it names the status the title lands on.
   - For a show it reads "Adds Severance to Watched, or Watching if it's still airing, ★★★★½".
   - `reviewEffect` is tested in Task 1.

### Task 1: Board rules in AaruCore (pure, tested)

**Files:**
- Create: `aaru-core/Sources/AaruCore/BoardRules.swift`
- Test: `aaru-core/Tests/AaruCoreTests/BoardRulesTests.swift`

**Interfaces (Produces).** AaruCore cannot see the generated types, so the comment rules are generic over a protocol that the app conforms `Components.Schemas.BoardComment` to:

```swift
public protocol BoardThreadComment: Sendable {
    var id: String { get }
    var replyTo: String? { get }
    var deleted: Bool { get }
    var authorHandle: String? { get }
    /// The same comment as a blank "Comment deleted" row: deleted, empty body, no author, not mine.
    func tombstoned() -> Self
}
public struct BoardThread<C: BoardThreadComment> { public let comment: C; public let replies: [C] }
public enum BoardRules {
    public static let pageSize = 20
    public static func stars(_ rating: Double) -> String            // 9 → "★★★★½", 10 → "★★★★★", 1 → "½☆☆☆☆"
    public static func ratingWords(_ rating: Double) -> String      // 9 → "4½ of 5 stars", 1 → "½ of 5 stars", 4 → "2 of 5 stars"
    public static func hasOlder(sortIsRecent: Bool, pageCount: Int) -> Bool
    public static func threads<C: BoardThreadComment>(_ items: [C]) -> [BoardThread<C>]
    public static func merge<C: BoardThreadComment>(_ current: [C], _ page: [C]) -> [C]
    public static func shouldLoadMore(next: String?) -> Bool
    public static func toggleUpvote(upvotes: Int, upvotedByMe: Bool) -> (upvotes: Int, upvotedByMe: Bool)
    public enum Empty: Equatable, Sendable { case noFriends, quiet }
    public static func empty(postCount: Int, friendCount: Int) -> Empty?
    public static func upvotersLine(_ names: [String]) -> String?
    public static func drop<C: BoardThreadComment>(_ items: [C], id: String) -> [C]
    public static func replyTarget<C: BoardThreadComment>(_ comment: C) -> (id: String, prefill: String)
    public static func prefillReply(_ text: String, from: String, to: String) -> String
    public static func remaining(_ text: String, limit: Int = 4000) -> Int?    // nil until fewer than 200 left
}
```

`reviewEffect` needs the per-kind status words that live in the app (`LibraryStatus.label(for:)`). It therefore takes them as arguments, so the rule stays tested:

```swift
public static func reviewEffect(title: String, isShow: Bool, inLibrary: Bool, rating: Double?,
                                finishedLabel: String, inProgressLabel: String) -> String?
```

- [ ] **Step 1: Write the failing tests.** These are ports of the web cases in `aaru-client/src/lib/board/model.test.ts`. Read that file and port every case, including:
  - `stars(9) == "★★★★½"`, `stars(10) == "★★★★★"`, `stars(1) == "½☆☆☆☆"`.
  - `ratingWords(9) == "4½ of 5 stars"`.
  - `threads`:
    - `C1, R1→C1, C2, R2→C1` gives `[(C1,[R1,R2]),(C2,[])]`.
    - A reply to a reply lands under its root.
    - A missing parent becomes top-level.
    - A cycle `A→B, B→A` gives two top-level threads and no hang.
  - `merge` dedupes by id and keeps first-seen order.
  - `shouldLoadMore(next: "x") == true` and `shouldLoadMore(next: nil) == false`.
  - `toggleUpvote(3,false) == (4,true)`, `toggleUpvote(4,true) == (3,false)`, and `toggleUpvote(0,true) == (0,false)`.
  - `empty(0,0) == .noFriends`, `empty(0,2) == .quiet`, `empty(1,2) == nil`.
  - `upvotersLine`: `[]` → nil; `["Ana"]`; `["Ana","Ben"]` → "Ana and Ben"; three names → "Ana, Ben and 1 other"; twelve → "… and 10 others".
  - `drop`:
    - A top-level comment with a live reply becomes a tombstone.
    - One without replies leaves.
    - Dropping the last live reply under a tombstoned parent removes both.
  - `replyTarget`: a top-level comment gives `(its id, "")`; a reply by ben gives `(its replyTo, "@ben ")`.
  - `prefillReply("", "", "@ben ") == "@ben "`, `prefillReply("hi", "", "@ben ") == "@ben hi"`, `prefillReply("@ben hi", "@ben ", "@ana ") == "@ana hi"`.
  - `remaining`: 3900 characters gives `nil`; 3850 gives `150`.
  - `reviewEffect`:
    - A new movie: `"Adds Arrival to Watched, ★★★★☆"`.
    - A new show: `"Adds Severance to Watched, or Watching if it's still airing, ★★★★½"`.
    - In the library: `"Updates your rating to ★★★★½. Its status stays."`
    - No rating: `nil`.

**Interfaces (Produces):**

```swift
@MainActor @Observable final class BoardModel {
    init(api: Client?)
    enum Sort: String, CaseIterable { case recent, top }      // labels "Recent", "Top this week"
    var sort: Sort; var posts: [BoardPost]; var hasLoaded: Bool; var loadProblem: String?
    var problem: String?; var canShowOlder: Bool
    func load() async                                   // listBoard(sort:), replaces posts
    func showOlder() async                              // before: posts.last?.id, recent only
    func post(body: String, title: CatalogHit?, rating: Double?, spoiler: SpoilerChoice) async -> Bool
                                                        // createBoardPost; inserts at top; spoiler → stamp/spoilerFree as Composer's SpoilerChoice does
    func toggleUpvote(_ id: String) async               // optimistic via BoardRules.toggleUpvote, rollback + problem
    func replace(_ post: BoardPost); func remove(_ id: String)   // the post screen reports edits/deletes back
}
@MainActor @Observable final class PostModel {
    init(api: Client?, postId: String, initial: BoardPost?)
    var post: BoardPost?; var unavailable: Bool; var upvoters: [SocialUser]
    var comments: [BoardComment]; var next: String?; var problem: String?
    func load() async                 // getBoardPost + listBoardPostUpvoters + listBoardComments in parallel; 404 → unavailable
    func loadMoreComments() async     // after: next, BoardRules.merge
    func comment(_ body: String, replyTo: String?) async -> Bool
    func deleteComment(_ id: String) async      // BoardRules.drop on success
    func edit(body: String) async -> Bool; func delete() async -> Bool
    func toggleUpvote() async
    func report(reason: Components.Schemas.ReportCreate.ReasonPayload, note: String?) async -> Bool
                                                // reportUser on post.author.userId; note prefixed "post:<id>" like the web's reportPost
}
func titlePosts(api: Client?, titleId: String) async -> [BoardPost]   // listTitlePosts; [] on any failure
```
